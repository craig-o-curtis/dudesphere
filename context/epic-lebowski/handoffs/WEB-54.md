- **Issue:** #90
- **Spec:** [issues/WEB-54.md](../issues/WEB-54.md)

## Scope

Nothing changes for members. Every page looks, reads and works as it did, apart from the small fixes the audit names. What changes is underneath. The app gets its first shared parts in `apps/web/src/components/ui/`, all native HTML on the WEB-6 tokens. Every existing component and page moves onto them, so each look is written once. AUTH-9 and every Phase 1 screen then compose parts instead of copying CSS.

## Decisions

Settled with the user in two rounds on 2026-10-15.

- **Field and Form:** our own native `Form`, `Field` and `FormAlert`. No form library, and no Base UI. `Field` also takes `invalid` and `errors` props, so a form library could drive it later. We compared TanStack Form, shadcn's Field, React Hook Form and Base UI Field. Only native parts keep the browser's own checks on with JavaScript off and put the hint and error ids in the server HTML without workarounds.
- **The JavaScript-off error test:** a Vitest spec renders the forms to HTML with an error state. It checks that the error text, `aria-invalid` and the hint and error links are in the server HTML. A Playwright test can't show this yet, because Next bug vercel/next.js#99756 gives a blank page. The known-bug e2e test stays as it is. So do the two JavaScript-off e2e tests that check the browser's own rules stop bad input.
- **ThemeToggle:** our own native `ToggleGroup`: a fieldset with a hidden legend, and buttons with `aria-pressed`. Base UI's ToggleGroup and shadcn's are not used, because they change the keyboard (one Tab stop and arrow keys), the screen-reader name and the focus guard before hydration.
- **SkipLink** becomes `ui/SkipLink`. SiteFooter keeps its `background` and top border in its own module. This is the one exception, written down in `audit.md`.
- **`@base-ui/react` is not added in WEB-54.** No part needs it yet. FEED-16 adds it with Dialog.
- **The `Form` part moves focus to the first invalid field** after a failed submit. The standalone `hooks/useFocusFirstInvalid.ts` is deleted, and its behaviour moves into `Form` with a spec.
- **`Field` clears a field's server error as soon as its value changes.** This fixes A11Y-3. With JavaScript on, the error text and `aria-invalid` go away while the member types.
- **The research is recorded** in a "Re-checked for WEB-54" section of `context/audits/forms-analysis.md`, covering TanStack Form, shadcn and React Hook Form. The library section of `context/audits/frontend-audit.md` is updated to say Base UI arrives with Dialog. The "When to bring in TanStack Form" guidance stays as it is.
- **Leftovers:** every row of the Gaps table below was accepted as proposed.
- **No date library**, ever, not even as an optional peer. Only `@northguild/gmt`.
- **All 8 "unused" tokens stay.** The parts read `--space-5`, `--space-7`, `--text-lg`, `--text-2xl` and `--color-success`. `lib/motion.ts` copies `--dur-fast` and `--dur-slow`. `--color-accent-2` is the rug red that RUG and LANE stories plan to use.
- **The spec's `themeColor` line is dropped.** `tokens.spec.ts` already checks it.
- **Page titles move from `line-height: 1` to `--leading-tight` (1.1)**, as `tokens.md` maps them.
- **The SessionCorner buttons gain the missing forced-colours border.**
- **SessionCorner's "Sign in" and "Sign up" become `ButtonLink variant="quiet"`.** The quiet variant keeps today's look: no border, no fill, bold, underlined.
- **Button variants:** sign-out buttons are `variant="secondary"`, and form submits are `variant="primary"`. Both match today's look.
- **`lib/auth-rules.ts`** holds `EMAIL_PATTERN`, its title text and every DTO limit the two forms copy. Each limit keeps its comment naming the DTO line it copies.
- **Field errors show as one sentence, joined by a space**, as today.
- **SessionCorner's fixed id** becomes `useId`, in a small synchronous child component.
- **Rendering strategies don't change.** `next build` must report `/`, `/login` and `/signup` exactly as before.
- **No mentor lesson.** The issue has no `rendering-lesson` or `auth-lesson` label.
- **No Tailwind helpers** (`class-variance-authority`, `tailwind-merge`, `clsx`). `lib/cx.ts` is the only class merger.
- **Field design, revised by the user mid-build (2026-10-15).** The compound `Field` is dropped. In its place: building blocks (`Label`, `Hint`, `ErrorMessage`, `TextInput`, `EmailInput`, `PasswordInput`, `CheckboxInput`, `SwitchInput`) and composed fields with a `Field` suffix (`TextField`, `EmailField`, `PasswordField`, `CheckboxField`, `SwitchField`). A composed field takes `name`, `label`, `hint` and the input's native props, and wires the blocks inside. One folder per part. Checkbox and Switch are built now, though no form uses them yet. See "Form and field parts (task 6)".
- **PasswordInput has a show-or-hide button with an eye icon.**
- **No zustand in WEB-54.** Form parts keep their state with `useState`. zustand comes in with the first story whose client state several distant components share (likely the R3F world or Lane Night), with a store per request in a context provider, as its Next.js guide says. Task 11 records this rule in `context/frontend-architecture.md`.

### Form and Field contract (task 6), superseded

Replaced by "Form and field parts (task 6)" below. `Form` and `FormAlert` were built to this contract and still hold. The `Field.*` points now apply to the composed fields.

- **`Form`** renders a native `<form>` and passes its props, `ref` and `className` through. It never sets `noValidate`. It takes `errors?: Partial<Record<string, string | string[]>>`, which matches `AuthFieldErrors`, and shares them through context. After a submit, when a new `errors` value arrives with at least one field error, it moves focus to the first control with `aria-invalid="true"` in page order. It does nothing on the first render. This is the old hook's behaviour.
- **`Field.Root`** takes `name`, and optionally `invalid` and `errors`, which override what `Form` sends. Its ids come from `useId` during render. It renders a `<div>` with `--field-gap`.
- **`Field.Label`** is a `<label>` whose `for` is the control's id.
- **`Field.Control`** is an `<input>` with the Root's `id` and `name`. It passes every native prop through (`type`, `required`, `pattern`, `minLength`, `maxLength`, `title`, `autoComplete`, `defaultValue`). When the field is invalid it sets `aria-invalid="true"`. Its `aria-describedby` names the hint id when a `Field.Hint` is rendered, and the error id while an error shows. Both are set during render, so they are in the server HTML. No id may point to an element that isn't rendered. When its value changes, the field drops its server error: the error text and `aria-invalid` go away until the next `errors` value arrives (A11Y-3).
- **`Field.Hint`** is a `<p>` with the hint id, in the muted small text look.
- **`Field.Error`** is the error id's element. It shows the field's messages joined by a space, in the danger tone, and renders nothing when the field is valid. It is not `role="alert"`. Focus and `aria-describedby` announce it, as AUTH-7's A11Y-1 fix does.
- **Component tokens:** `--field-gap`, `--input-bg`, `--input-border`, `--input-border-invalid`, `--input-radius` and `--input-min-height`. Under `@media (forced-colors: active)`, an invalid input gets a thicker or different system-colour border, so the invalid state shows without colour (A11Y-2).

### Form and field parts (task 6)

`Form` and `FormAlert` are done, as in the old contract. `Form` exports `FormErrorsContext` and the type `FormErrors`.

**Building blocks.** Each one is server-safe unless noted, takes `className` (through `cx`), `...rest` and `ref`, and knows nothing about auth. Feature rules such as `EMAIL_PATTERN` come from the caller.

- `Label`: a `<label>`. It takes `htmlFor` and `children`.
- `Hint`: a `<p>` with an `id`, in the muted small look.
- `ErrorMessage`: the error element with an `id`. It shows its messages (a string or a string array) joined by a space, in the danger tone, and renders nothing when there are none. It is not `role="alert"`.
- `TextInput`, `EmailInput`: an `<input>` with `type` set to `text` or `email`. They own the input look and the component tokens `--input-bg`, `--input-border`, `--input-border-invalid`, `--input-radius` and `--input-min-height`. They show the invalid look from `aria-invalid="true"`, with the forced-colours invalid border (A11Y-2).
- `PasswordInput` (`"use client"`): an `<input type="password">` with the same look, plus a show-or-hide button with an eye icon and a crossed-eye icon. The icons are inline SVG with `aria-hidden`, and no icon library comes in. The button is `type="button"`, named "Show password", with `aria-pressed` and `aria-controls` set to the input's id. Its state is `useState`. With JavaScript off the button can't work, so it isn't shown or usable before hydration, and the layout doesn't shift when it appears. The input keeps its `name`, `autocomplete` and native rules in both states. The button meets `--target-min` and shows a focus ring.

**The shared hook.** `components/ui/Field/useField.ts` (`"use client"`, with a spec) does the wiring once for every composed field.

- It makes the ids with `useId` during render, so they are in the server HTML.
- It reads errors with `use(FormErrorsContext)?.[name]`. The field's own `errors` and `invalid` props override them.
- It clears the error on edit (A11Y-3) with no effect: it keeps the errors value that was cleared in state, and shows errors only while that differs from the current value. The caller's own `onChange` still runs.
- It returns the input props (`id`, `name`, `aria-invalid`, `aria-describedby`, `onChange`) and the hint and error ids. `aria-describedby` names only elements that are rendered.

**Composed fields** (`"use client"`): `TextField`, `EmailField`, `PasswordField`, `CheckboxField` and `SwitchField`.

- Each takes `name`, `label`, an optional `hint`, optional `errors` and `invalid`, and the native props of its input.
- `TextField`, `EmailField` and `PasswordField` render, in today's order: `Label`, the input, `Hint` when there is one, then `ErrorMessage`. The gap is `--field-gap`.
- `CheckboxField` and `SwitchField` render the input and its label on one row, then `Hint` and `ErrorMessage`.
