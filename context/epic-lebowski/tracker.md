## Phases

Each phase is one GitHub milestone, named exactly as below.

- `Phase 0: Foundation`: rows 1 to 11. The monorepo, the web shell, auth through the BFF, and the rendering-strategies guide.
- `Phase 1: The Feed`: rows 12 to 21. Passwordless sign-in, then the Twitter part of the app.
- `Phase 2: Lane Night`: rows 22 to 29. The anchor: async bowling and the Score Sheet.
- `Phase 3: Rituals and identity`: rows 30 to 37. Check-ins, the timer, quiet mode, the Rug, the quiz, the certificate and the Stranger.
- `Phase 4: Achievers`: rows 38 to 45. Groups, Bowling Nights, recipe posts and moderation.
- `Phase 5: Polish and deploy`: rows 46 to 48. Deploy, browser tests, and a performance and accessibility pass.
- `Later`: rows 49 to 52. Tracked, not scheduled.

## Definition of Done

Every story meets every line below before its row says `Done`.

- The code and its tests are merged to `main` through a PR.
- A backend story has unit specs and e2e specs. The e2e specs follow the repo's rules:
  - users are `e2e-` prefixed, with an `e2e-...@example.com` email;
  - hashtags are `e2e` plus 12 lower-case hex characters;
  - every new table is added to the cleanup in `apps/api/test/global-setup.ts`.
- Every Postgres change goes through a migration in `apps/api/src/database/migrations/`. Migrations are append-only.
- Every date goes through `@northguild/gmt`. No code holds a `Date`.
- `pnpm lint`, `pnpm format:check` and `pnpm typecheck` pass, and every CI job is green.
- A web story works with the keyboard alone and under `prefers-reduced-motion: reduce`.
- The rendering strategy the story uses is recorded in `context/epic-lebowski/rendering-strategies.md`.
- The docs are updated. An API change updates `context/overview.md`.
- This tracker's row is set to `Done`, and the GitHub issue is closed.
